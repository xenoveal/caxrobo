# Plan: v0.3.1 — Multi-Detector Strategies + Evolution Replay UI

## Summary
Two features. **[1]** Let the Composer build strategies with MULTIPLE detectors (one branch per detector — the backend graph model and the `mutator.graph-edit` search already support this; only the linear composer and its HTTP mapping enforce "exactly one detector"), and let the operator pick an **eligible-detector set** that constrains which detectors evolution may swap in / add, carried in `graph.meta` so it rides the seed graph into the campaign with zero runner plumbing. **[2]** Replace the Evolution tab's bare table with an interactive replay dashboard: a sidebar of generations → members, and an animated candlestick chart that plays a member's evaluation window bar-by-bar, highlighting each detected pattern with its entry / stop / target levels (like a marked-up pattern chart), backed by two new read-only API endpoints that re-derive trades deterministically (never touching the trial ledger).

## User Story
As the bot's operator, I want to compose strategies from several pattern detectors, restrict which detectors evolution may explore, and watch any population member trade its window bar-by-bar, so that I can actually understand what each evolved model does instead of reading a fitness table.

## Problem → Solution
- Composer allows exactly one detector; multi-branch graphs render read-only → Composer maps N detector stages to N branches (shared policy/exits/confirmations) and round-trips uniform multi-branch graphs back into stages.
- `mutator.graph-edit` swaps/adds ANY registered detector → it honors `meta.evo.eligible_detectors` when present, so search stays inside the operator's chosen pool.
- Evolution tab = load button + static table → sidebar (campaign → generation → member) + animated OHLC replay with trade overlays (entry/SL/TP), position panel, play/pause/speed/scrub; the old table survives as a "Table" toggle.
