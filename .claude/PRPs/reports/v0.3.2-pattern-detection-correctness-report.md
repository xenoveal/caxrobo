## Candlestick mandate

Per the user's instruction that a line chart is too weak to detect patterns,
every new test reads OHLC, never closes:

- Dominance guard reads `df["low"]` / `df["high"]` over the bar range, not the
  pivot list — an unconfirmed spike that never became a fractal pivot still
  disqualifies a pair.
- Prior-trend reference reads the opposite candle extreme over a neighbourhood
  of the anchor bar.
- `trend-context` reduces each half-window to `mean((high + low) / 2)`; no part
  of its measurement touches a close.

One deliberate exception, argued rather than overlooked: `_geometry.level_unbroken`
stays close-only. It answers "is this pattern already spent", and a wick through
the level that closes back inside is a stop-hunt, not a confirmed break. **This is
a judgment, not a measurement.**

## Measured impact — read this before trusting any backtest

Structural double-top/bottom candidates on BTCUSDT 4h, full stored history
(7,821 bars):

```
double-bottom: 789 -> 140  (82.3% removed)
double-top:    820 -> 212  (74.1% removed)
```

**Caveat, as reported by the implementing agent:** these are raw structural pairs
across the whole history, not backtest trades. They do not apply per-bar
`fresh` / `level_unbroken`, and do not run `dedupe_events`, both of which already
shrink the "before" figure in a real backtest. It is a reproducible measure of
how much the raw structural pool shrinks — **not** a verified trade-count delta.

**Consequence: every existing backtest number describes code that no longer
exists.** The removed candidates were false positives and removing them is
correct, but nothing here measured what the *remaining* patterns earn. The
validation gate was already failing before this work (5 of 7 conditions,
champion -45.47% over the 182-day holdout, `KNOWN-LIMITATIONS-v0.3.0.md`).
Better geometry is not a working strategy.

## Not done

- **No `detector-report` / backtest re-run.** This is the required next step and
  is the only thing that can say whether the fixed detectors have any edge.
- **No browser verification of the chart.** Vertex derivation, sorting, clamping
  and tier fallback were verified in isolation; the rendered SVG was not viewed.
- **`trend-context` is registered but not wired** into any default strategy
  graph. Its defaults (`lookback=20`, `min_trend_frac=0.03`) are explicitly
  **unmeasured starting points** — at those values on BTC 4h the gate likely only
  catches extreme cases and may pass ordinary chop. Needs an ablation.
- **Other pattern families were not audited for the same defect class.** The
  code review found, and this plan did not address:
  - `_geometry.fit_converging_lines` fits each triangle/wedge boundary through
    only the first and last pivot per side with `min_pivots_per_side` defaulting
    to 2, and never requires intermediate pivots to *touch* the lines — so a
    "triangle" can be four pivots around empty space.
  - `cup-and-handle`, the flags, and the triangles all still have no prior-trend
    requirement of their own; `trend-context` can now supply it, but no graph
    uses it yet.
- **`dedupe_events` still keeps the largest `target_height`**, biasing toward the
  widest rather than the cleanest pattern. Left alone deliberately — it is shared
  by every detector.
