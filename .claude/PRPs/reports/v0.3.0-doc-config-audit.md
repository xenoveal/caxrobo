## Deprecated and untracked

is now **4.19 MB (−80.3%)**. Every file remains on disk and recoverable from history; sizes,
sha256 sums, per-file `git show` recovery commands and regeneration commands are in
[DEPRECATED-ARTIFACTS.md](DEPRECATED-ARTIFACTS.md).

Rule applied, stated so it can be audited rather than argued with: *untrack a generated
artifact over 100 KB; keep every authored document, every test fixture, and every small
artifact a live document cites as evidence.* Two of the five (13.9 MB) were referenced by
nothing at all.

**Honest limit of this action**: history was deliberately **not** rewritten, so a fresh clone
still downloads the 17.1 MB. Reclaiming it needs `git filter-repo` and a force-push on a
published branch — that is a separate decision, documented but not taken.

### Advisory, not acted on

- **The venv's installed metadata says `0.1.0`** (`trading_bot-0.1.0.dist-info`, `__editable__.trading_bot-0.1.0.pth`) — it predates both 0.2.0 and 0.3.0. Harmless today because **nothing reads the version at runtime** (no `importlib.metadata`, no `__version__`), but `pip install -e .` would resolve the three-way mismatch.
- **No linter and no type checker are configured.** `KNOWN-LIMITATIONS-v0.3.0.md` §8 already states this honestly rather than inventing a command. Adding `[tool.ruff]` would be a new gate on 1252 passing tests — a scope decision for the owner, not a docs fix.
- **`src/trading_bot/cli.py` is ~2,350 lines**, well past any reasonable file-size threshold. Out of scope here; flagged for whoever next touches the CLI.
- **`.env.example` is tracked but nothing loads `.env`.** With `python-dotenv` correctly removed, a user copying `.env.example` to `.env` gets silently empty credentials. Only `BINANCE_API_KEY`/`BINANCE_API_SECRET` are read (`exchange/binance_client.py:71-72`), both defaulting to `""`, and public OHLCV endpoints need no credentials — so this is misleading rather than broken. A one-line note in `.env.example` saying the vars must be **exported** would close it; that file is outside this session's write permissions.
